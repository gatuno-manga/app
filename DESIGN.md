# Design System: Gatuno

**Source of truth: the Figma file, not the code.** Values below come from the Figma variable collections `Gatuno / Tokens (código)` and `Gatuno / Leitura (temas)` and the Figma text and effect styles. `AppTheme` (`lib/core/theme/theme.dart`, palettes in `app_palette.dart`, text styles in `app_typography.dart`) implements it; remaining drifts are collected in [Figma vs code gaps](#figma-vs-code-gaps). This intentionally overrides the `document` reference's "theme code is normative" rule for this repository (issue #40). Machine-readable tokens, with Figma names, live in `.impeccable/design.json`; the two files must agree (`python3 tool/check_design_tokens.py`).

## Overview

**Creative North Star:** not decided. The Figma file does not name one and none was confirmed; do not invent one.

The Figma system is dark-first: warm cream text (`#e9e1d1`) on near-black blue (`#000212`) with one orange accent (`#f18522`), serif titles (Inknut Antiqua), and glass (blurred translucent) surfaces for menus, sheets and overlays. Five themes share one set of semantic token names; only the values change.

**Key Characteristics:**
- Semantic tokens first: components reference `color/primary`, never a raw hex.
- Translucent tints (`-10`, `-15`, `-40` alpha ramps) instead of separate light/dark shades.
- Three type voices: Inknut Antiqua (titles), Manrope (body), Plus Jakarta Sans (interface labels); reader-only Literata and Lexend.
- Flat surfaces; depth comes from glass blur and one shadow style, not from layered elevation.

### Reader themes
`Gatuno / Leitura (temas)` has four modes (Padrão, Sépia, Creme, Alto contraste) with `leitura/fundo`, `leitura/superficie`, `leitura/texto`, `leitura/texto-suave`, `leitura/acento`, `leitura/destaque`, `leitura/borda`. They apply only inside the reader (frame `882:910` uses Creme with the dyslexia preset). Code: `ReaderPalette` (`lib/core/theme/reader_palette.dart`, a `ThemeExtension`) holds Sépia, Creme and Alto contraste as constants; Padrão is built from the active `AppPalette` (`ReaderPalette.fromAppPalette`), so it follows the chosen app theme. The text reader applies the chosen palette to its own subtree through `ReaderThemeScope` (`features/reading/presentation/theme/`), which overrides `colorScheme.surface`, `onSurface`, `primary`, `outline` and the container roles; the image reader does not use it yet.

### Named Rules
**The Semantic Token Rule.** Never hardcode a color in a screen; use the semantic token. Code today violates this with `AppColors.*` constants used directly (see gaps).
**The One Accent Rule.** `color/primary` is the only brand accent in a theme. `color/lilac` and `color/cyan` are fixed accents shared by all themes, not alternates for primary.

## Typography

**Figma families:** Inknut Antiqua (titles), Manrope (body), Plus Jakarta Sans (interface). Reader only: Literata (serif reading), Lexend (dyslexia preset); the reader font picker also offers Atkinson Hyperlegible and OpenDyslexic (see gap `reader-fonts-not-in-figma`). **Code:** all five families are bundled (`assets/fonts/`, declared in `pubspec.yaml`, OFL licences alongside; Manrope also at 500/600/700 and Literata/Lexend at 700 so Material bold does not synthesize). ## Layout

Mobile frames are 390×844 with a bottom navigation bar, a top app bar per screen and sheets instead of side menus (page "04 · Telas Mobile (App)", page note `859:30`). Tablet frames (834×1194 and 1194×834) are on page "05 · Telas Tablet (App)" and use a navigation rail instead of the bottom bar (see "Window size classes and tablets"). The desktop/web layout uses a fixed side menu at 1200px and above (frame `912:2803`), at 1440px width. The web shell (`Web/Organism/Shell web/Header`, `Web/Organism/Shell web/Menu lateral`, `Web/Molecule/Shell web/Item de navegação`) is not used on mobile.

### Navigation model (phone, issues #168 and #169)

- **Bottom bar** for the top-level destinations: Início, Biblioteca and Livros (PT labels; Home, Library, Books), three items. Settings is not a tab. Library is visible to guests, where its screen shows a sign-in prompt; until #130 ships the Biblioteca tab is a placeholder screen with an empty state saying the library is coming, so the bar has three items from the start. The component keeps `Items=4` for a later fourth destination. The frames draw it as `Items=3` with the labels and icons overridden on the nested items (the component's own default labels are Início, Livros and Configurações).
- **No drawer.** Where the drawer entries went: Perfil and the settings are one pushed screen, "Perfil e configurações", opened from an avatar action in the top bar of every tab root (guests see a user icon in the same slot); Últimas leituras is "Ver tudo" on Home (#132); Livro aleatório is an action on Livros; Dashboard stays on the web. The screen has the profile card on top (a sign-in card for guests), the settings and a row for book requests (`/requests`, signed-in users only). Book requests has two entries: the call-to-action card on Home and that row. Editing the profile (`/settings/profile`) is a second pushed screen above it.
- **Top bar per screen (one row).** Every bar is one 64 dp row: the title (or, on Home, the logo) on the left and up to three 48 dp actions on the right. Tab roots no longer have a large title on its own row (#266; the `Expanded root` of #169 is gone). Livros adds a 56 dp search row to the bar (`Root with search`, 120 dp); the row is part of the bar, so it hides and returns with it and is not pinned. Pushed screens show back, a left-aligned title and actions in the same 64 dp row. The bar hides on scroll down and comes back on scroll up (behaviour, not a Figma state). Titles are left-aligned everywhere; frames that centred them (`/requests`, `/settings/certificates`) were redrawn in #170. Up to three actions of 48 dp; no notifications bell until #97. The last action on tab roots is the profile avatar (`Core/Atom/Avatar/Perfil`, 24 dp: the user's image, a generic user icon when there is no image; guests see the Guest state in the same slot).
- **Bar and tab selection.** Pushed screens inside a tab keep the bottom bar and the tab they were opened from; readers, auth and welcome hide it. The merged profile and settings screen, requests and certificates are pushed from a tab, so they keep it selected (the frames draw Início). A book detail opened from Home keeps Início selected, so the detail is pushed on the Home stack.
- **Native behaviour** (code, #172): system and predictive back, swipe back on iOS, re-tap pops to the tab root and then scrolls to the top, one stack per tab, safe areas and the gesture inset around the bar.
- **Sizes.** The bottom bar is 80 dp tall (Material 3 navigation bar with labels), not counting the system gesture inset below it; the code bar is 48 dp without labels today. The top bar is 64 dp, and 120 dp with the search field of Livros (64 dp row plus a 56 dp row).

### Section order of the phone and tablet pages (issue #266)

Related screens sit next to each other. Page "04 · Telas Mobile (App)", top to bottom: Descoberta (Home, Últimas leituras, Livros, filters), Livro (`/books/:id`), Leitor, Biblioteca e Perfil, Boas-vindas, Autenticação (sign in, sign up), Autenticação — MFA (`/auth/mfa`, right after Autenticação), "Configurações — /user" (`/settings`, the merged screen), Configurações — MFA, Bloqueio do app, Certificados, Solicitações. Page "05 · Telas Tablet (App)": Home, Livros, Livro, Biblioteca, Últimas leituras, Perfil e configurações, Autenticação e boas-vindas. The frames that sat loose on the page 04 canvas (`/home` visitante and offline, `/books` and `/library` bar states, `/library` placeholder and visitante, `/settings` visitante) are inside their sections, and sections that overflowed (Configurações, Livro, Biblioteca e Perfil, Descoberta) were grown to fit.

Foldables and multi-window fall into the same classes. The tablet frames live on page "05 · Telas Tablet (App)" (`1100:8297`, page note `1109:11021`), in one section per area, each screen drawn at both sizes; the surface files list them under "Tablet frames".

- **Rail, no drawer.** From medium up, the bottom bar becomes the navigation rail, with the same three destinations (Início, Biblioteca, Livros), icon above label, the same selected state and the optional badge. It is 80 dp wide, the Material 3 default: the longest label is "Biblioteca" (59 dp at 12 dp), which fits with 10 dp on each side. It is top-aligned, `color/app-background` with a 1 dp `color/border` line on its right edge, and fills the window height. There is one rail for both classes: no extended rail and no permanent side drawer, which would bring back the web sidebar. Full-screen flows (readers, auth, welcome) hide it, as they hide the bottom bar.
- **Top bar.** The #169 variants of `App/Organism/Shell/Barra superior` work at tablet widths unchanged: the instance fills the content area beside the rail (the inner row and the search field are set to fill) and the actions stay at the right. No tablet variant was needed.
- **Adaptive grids.** Book grids take their column count from a minimum card width of 160 dp with 16 dp gaps and 24 dp side padding: 4 columns at medium and 6 at expanded (cards of about 160 dp, cover 2:3). List cards (`Core/Molecule/Livro/Card` List) use a minimum width of 320 dp: 2 columns at medium and 3 at expanded. Phones keep 2 columns.
- **Home.** The carousel (`Core/Organism/Home/Destaque`, variant Platform=Tablet) is capped at 360 dp tall instead of the 620 dp of the phone; its glass panel puts the cover and the text side by side. Book rows show 4 (medium) or 6 (expanded) cards.
- **Book detail** (`/books/:id`). Medium: one column with a wide header (cover on the left, title, authors, action buttons and the continue button on the right), then tags, synopsis, tabs and the chapter list. Expanded: two panes, the cover and metadata panel (384 dp) on the left and the tabs with the chapter list on the right (chapter rows use the wide `Core/Molecule/Capítulo/Item` layout).
- **Profile and settings** (`/settings`, the pushed screen "Perfil e configurações" opened from the avatar action in the top bar of every tab root; the tab it was opened from stays selected, Início in the frames). Medium: as on the phone, one column with `App/Organism/Shell/Barra superior` Stacked, and sub-pages are pushed. Expanded: list-detail, the settings list (400 dp) on the left and the sub-page on the right (profile, downloads, certificates, app lock, MFA). The first entry is selected on open (profile for signed-in users, Downloads for guests), so the detail pane is never empty. The "Solicitar livro" row pushes `/requests` instead of opening in the detail pane. The selected row has a `color/primary-15` fill.
- **Content widths.** Forms (sign in, sign up, welcome) are 480 dp wide at most and centered; text-heavy pages (settings sub-pages, certificates, synopsis) are 720 dp wide at most; grids and lists use the full width. A column narrower than its maximum fills the available width.
- **Sheets on wide screens.** Bottom sheets are 640 dp wide at most and centered at the bottom edge. On expanded, the books advanced filters open as a modal side sheet of 360 dp on the right edge, over a `color/app-background` scrim at 60% opacity, opened by the same button as the phone sheet. On medium, the filters use the centered bottom sheet.
- **Library and latest reads** (`/library`, `/latest-reads`): adaptive list grids (2 and 3 columns), with an empty state at both sizes. They are references for #130 and #132; no code task in #168 builds them.

Spacing scale (same in every theme): `space/xs` 4, `space/sm` 8, `space/md` 12, `space/lg` 16, `space/xl` 20, `space/2xl` 24, `space/3xl` 40 dp. Mobile section content uses 16 dp horizontal padding (`space/lg`) in the Home frame `913:1380`. No spacing tokens exist in code.

### Naming scheme

Every component in the Figma file is named `<Platform>/<Tier>/<Group>/<Name>` (decided in #264, part of #263). The code mapping below uses the full name.

- **Platform**: `Core` (used by both the web and the app frames), `Web` (only web frames) or `App` (only app frames). Decided by frame usage; a generic primitive that only app frames use today (`Campo/Texto`, `Esqueleto`, `Diálogo/Confirmação`) is `App` until a web frame uses it, then it is renamed to `Core` (the node ID stays).
- **Tier**: `Atom`, `Molecule`, `Organism` or `Template` (English, the same words as the code folders). Decided with the rules in `AGENTS.md` ("Deciding the tier"). There are no `Template` components yet.
- **Group/Name**: the name the component had before #264 (`Shell/Barra inferior`), unchanged, so it stays searchable. Icons and the logo follow the same scheme (`Core/Atom/Ícone/home`, `Core/Atom/Marca/Logo`) and stay where they were (page "01 · Padronizações" and the logo cell).
- **Variant properties, values and component properties** are English, and the same concept has the same name in every set (`State`, `Type`, `Variant`, `Platform`, `Selected`, `Label`, `Title`, `Show ...`, `Yes`/`No`). Text in frames (labels users read) stays Portuguese.
- **Page "02 · Componentes"** has the sections `Core`, `Web` and `App`, each with `Atoms`, `Molecules` and `Organisms` subsections (`Templates` appears with the first template). No node ID changed in the move.

## Do's and Don'ts

### Do
- **Do** reference semantic token names (`color/primary`, `radius/md`, `Título/2`) when describing or reviewing UI.
- **Do** keep text on `color/primary` in `color/on-primary`.
- **Do** respect the sensitive-content preference from Settings; Figma shows the visible-sensitive state in frame `925:4590` (uses the `Core/Atom/Bandeira` component).
- **Do** support EN and PT strings through ARB keys, with room for longer Portuguese labels.

### Don't
- **Don't** introduce colors, radii, spacing or fonts that have no Figma variable or style; record a gap instead.
- **Don't** use the `Gatuno / The Cheap Weekly` collection (redesign exploration) as product tokens.
- **Don't** treat the current `AppTheme` values as the target where they differ from Figma.
